# 食物优化：user1 熊熊星球 T0 的下一步提速

2026-09-08。输入为工作区 `tmp/user1.json`，熊熊星球 T0，24 小时，10% 网格，1 轮，应用默认种子。已实施有限优先搜索与装备属性复用，见 [第 6 节](#6-已实施有限优先搜索与装备属性复用)。第 1～5 节保留实施前的诊断和原型记录，其中“当前实现”均指实施前版本。

## 1. 已复现的瓶颈

通过应用的正式导入、角色映射和候选构造流程，得到 **HP 1,643、MP 1,920、3 槽、4,406,403 个候选**，与用户记录一致。Node.js v22.20.0，AMD Ryzen 7 8845H，真实 Worker 上限 4。角色价格数据未提供，试验使用已有商店价回退；未启用队友、战斗卷轴和社区增益。因此不能把本机时间直接等同于用户浏览器时间，价格有关的排名也不代表用户当前市场价排名。

用户在 1,471.8 秒时处理了 521,009 个候选，约占 11.82%；490,992 个空蓝，30,017 个死亡超限，仍没有可行候选。289,482 个候选已被现有证据提前排除，约占已处理量的 55.56%，所以不是所有复用都没有生效。单轮缓存主要接受完整且未空蓝的轮次，失败占绝大多数时“单轮结果复用 0”并不能单独证明缓存故障。

没有十个已证明可行的候选，就没有可用于精确前 10 的成本界限；增加排名剪枝规则解决不了这个阶段。现有引擎已经在首次空蓝或死亡超限事件后停止模拟，也不能把“失败提前停”当成尚未实现的新方向。

### 全组合默认方案诊断

独立模拟所有 3,683 个组合的默认阈值，得到：

| 结果     | 组合数 |
| -------- | -----: |
| 可行     |    180 |
| 空蓝     |  3,039 |
| 死亡超限 |    464 |

第一个可行默认组合出现在现有顺序的 **第 1,338 位**，当前装备的三食物组合出现在 **第 3,191 位**。当前装备基线在这组种子下 24 小时零死亡、未空蓝，其默认阈值组合也可行。用户记录的“前 768 个默认组合全部失败”与这个分布吻合，不能据此认定没有可行方案。

当前搜索以 32 个组合为一窗，先做默认候选，再展开该窗的阈值变体。它会在抵达后面的可行组合前，花大量时间遍历前面失败组合的变体。全部默认组合这次诊断耗时 187.5 秒；这个数字是独立的全默认检查，不是完整食物搜索时间，也不是建议每次增加 187.5 秒预筛选。

## 2. 首选方向：当前装备组合优先，再从默认阈值附近展开

利用已经存在的当前装备信息，先处理其食物组合，再继续原有组合全集。只改变访问顺序，不直接把原装备当作网格中的可行证明：实际候选仍经过规范槽序构造和完整模拟。

在优先组合内，阈值从自己的恢复量对应默认值附近开始，再遍历较远阈值。所有值都来自原网格；原型保留候选全集和排名规则。这个顺序主要用于尽早建立可行榜单和有效成本界限。

### 全目录 60 秒试跑

以下均为单次、有 60 秒预算的**部分搜索**，均没有完成全域最终排名。时间包含 Worker 启动和基线。

| 原型                                | 首个可行候选 | 首次拥有 10 个可行候选 |
| ----------------------------------- | -----------: | ---------------------: |
| 当前生产顺序                        |  60 秒内没有 |            60 秒内没有 |
| 当前装备组合优先                    |      5.81 秒 |               55.88 秒 |
| 当前装备组合优先 + 默认阈值附近优先 |      4.39 秒 |               11.96 秒 |
| 上一项 + 装备属性复用               |      3.76 秒 |                8.53 秒 |

这说明能显著缩短“长时间没有任何结果”的等待，**不是证明 8.53 秒完成四百多万候选的精确搜索**。优先处理的可行候选可能需要跑满 24 小时，部分搜索的已处理数量也不能与先遍历失败候选直接比较速度。

当前原型会先展开这个组合的全部阈值。正式实施还值得把优先搜索限定为少量邻近候选：得到足够的可行界限后，恢复正常全域调度，避免长时间停留在一个组合。需要继续验证去重、覆盖、取消和无可行邻域时的回退。

## 3. 独立提速方向：复用搜索期间不变的装备属性

对这份角色的失败候选进行 15 秒 CPU 采样，覆盖 544 次实际模拟。角色 `Player.updateCombatDetails` 及子调用约占采样的 **41.8%**，其中装备 `getCombatStat` 自身约占 **13.2%**。增益施加、过期会反复触发重算，装备汇总也随之重复。

原型只在食物模拟创建的独立角色实例上缓存装备属性汇总，增益和最终派生属性仍按原流程重算；缓存值只替代原装备汇总循环写入的字段。它没有缓存当前 HP/MP、技能或食物冷却、随机数状态。

这不是消除整个 41.8% 热点。正式实现必须限定不可变的模拟装备上下文，保持普通预览、换装、强化修改和方法覆写的正确行为，不能对所有 `Player.updateCombatDetails` 无条件复用。

### 固定失败子集的三次计时

使用同一个真实角色、熊熊星球 T0、24 小时 × 1、10% 网格，食物缩为甜甜圈、黑莓甜甜圈、软糖、酸奶，共 6,095 个候选，全部不可行。每组各三次，轮换运行顺序；计时关闭覆盖展开检查，包含真实 Worker 启动、基线和退出。

| 版本                              |    中位耗时 | 相对当前 | 实际模拟轮数中位数 |
| --------------------------------- | ----------: | -------: | -----------------: |
| 当前实现                          | 12,569.2 ms |    1.00× |              3,489 |
| 装备属性复用                      |  9,113.5 ms |    1.38× |              3,502 |
| 装备属性复用 + 失败跨组合复用原型 |  5,996.8 ms |    2.10× |              1,531 |

这个对比是完整跑完固定子集的时间，不是“首次出榜”时间。该子集不能代表全 28 食物的总体收益；装备属性复用基本不改变实际模拟量，收益主要来自每次模拟变便宜。

## 4. 保留方向：跨组合复用已证明的空蓝失败

现有同组合阈值证据已经可以复用失败。新增空间在于：一个组合吃过 A 后仍然空蓝，若 B 在该失败轨迹的所有食物检查位置都不会触发，就可以将失败证明用于 A+B 的相应阈值区域；两个已消费食物也可以作为核心，但必须保持它们的实际槽序。

原型只接受请求种子中的明确空蓝终态，并使用失败前缀的核心阈值证据与额外食物不触发证据。它作为独立的不可行证明，不冒充成功的完整单轮结果，不参与可行方案成本汇总。累计死亡与跨轮剩余预算不在这个原型的扩展范围内。

失败子集的初次覆盖审计中，实际模拟从 3,489 轮减少到 1,599 轮，全部 6,095 个候选的覆盖与不可行分类一致。但是全目录前 60 秒中，简单原型处理了 36,168 个候选，当前实现为 37,072 个；原型执行约 4.6 万次额外查询，未见前段提速。

因此不能直接把“小域快 2.1 倍”的叠加结果推广到全目录。后续应先改成直接按消费核心查询、过滤没有扩展价值的证据，并测量当前活动组合的命中率。查询收益不足时应回退；不宜先无条件扩大缓存。

## 5. 实施优先级与验证边界

建议先落地 **当前装备附近的有限优先搜索 + 食物模拟内的装备属性复用**，分别改善首次得到可用候选的时间和每轮计算成本。失败跨组合复用需要进一步减少索引开销，再决定是否加入。

本轮重点为普通地图。地下城可以共享装备计算优化，但组合优先策略仍需单独回归，不能把熊熊星球数据当作地下城实测。

当前的完成性检查包括：6,095 候选的失败子集覆盖对照，以及当前装备三食物各取原网格附近三点组成的 64 候选小域。后者包含可行候选，当前顺序、装备附近优先、叠加装备与失败复用三种实现均完整结束，候选覆盖与最终物理榜单一致。64 点子域仍不是全目录验证。

64 个候选另逐项运行了 **24 小时的独立完整原生引擎**，使用通用触发器与原始增益查询，完成三种实现共 **192 次候选分类对账**，基线与最终前 10 的逐轮物理结果一致。实际可行但被成本排除的候选均严格落后独立第十名。

装备属性复用另核对当前装备基线、六个失败方案和四个可行方案，共 11 条轨迹。前后 **610,453 次事件、2,669,274 次随机数调用、125,632 次角色属性重算**的数量和顺序摘要完全一致，最终消费、死亡、空蓝、停止时刻和阈值证据也一致。校验按实际模拟边界执行：可行方案与基线跑满 24 小时，失败方案到首次失败事件为止。

这些正确性检查不计入性能样本。对诊断开始时记录的 78 个生产源文件重新计算 SHA-256，均没有变化；本轮没有为研究重复运行全项目测试或构建。

原始脚本与数据保存在忽略目录 `tmp/food-optimizer-user1-research`，角色原文件没有修改；没有启动项目或浏览器。主要报告：

- `full-pilot-60s.json`、`near-pilot-60s.json`：全目录预算试跑，运行状态为取消，不能当作完整耗时。

## 6. 已实施有限优先搜索与装备属性复用

有限优先搜索只用于精确前 10：保留空食物检查，随后优先处理当前装备的两种或三种不同食物。每种食物取规范默认阈值附近至多三个原网格点，默认候选加邻近变体合计最多 27 个；处理后恢复全目录调度。空食物已经可行或已有界限时不增加这段搜索，完整统计模式保留原顺序。

已经处理的默认候选不会再次派发或计数；已处理的邻域从该组合后续遍历中扣除，余下区域按“第一个落在邻域外的轴”划分，至多六个互不重叠的区域。原候选全集、实际槽序和排序规则保持一致，当前装备基线不能直接冒充网格候选的可行证明。

装备属性复用在食物模拟创建角色时启用，适用于普通地图和地下城的两种搜索模式。缓存只属于当前模拟角色，保存装备汇总循环写入的原始字段，增益及最终派生属性仍正常重算。换装、卸装、强化和属性表引用改变会使缓存失效；自定义装备方法、属性访问器及原型方法覆写回退。模拟期间共享游戏物品定义保持不变，不缓存战斗中的生命、法力、冷却或随机状态。

新增 44 项测试覆盖邻域及补集分割、乱序与不规则网格、并发、压缩复用、邻域外的更优结果、跨窗口去重、取消与失败清理，以及装备缓存失效。全量 **166 个文件、2,218 项测试**全部通过；Prettier 和生产构建通过，构建保留已有的大包提示。

相同角色、地图、时长、种子和价格回退，失败子集仍为 6,095 个候选。这个子集没有当前装备的食物，优先搜索自动停用，因此能单独观察装备属性复用的效果。每组测三次，轮换顺序；计时包含真实 Worker 启动、基线和退出，关闭覆盖审计，没有与测试或构建并行。

完整耗时减少 **26.2%**，约 **1.36 倍**速度。这里使用本轮生产代码的实测值，不能将前文原型数据替换进这组对比。另行覆盖审计确认新旧均恰好处理全部 6,095 个候选，空蓝判定一致。
